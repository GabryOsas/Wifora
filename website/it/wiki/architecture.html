Architettura del Sistema

Come è fatto Wifora dentro: componenti, flusso di una sessione, ciclo di vita delle stanze e mappa dei moduli sorgente.

Componenti

[PC Windows — Host]
  Browser (Chrome/Edge)          Helper WASAPI opzionale
  ├─ getDisplayMedia loopback    wifora-audio.exe
  │   └─ Web Audio DSP               └─ stdout PCM Float32 (WFR1)
  ├─ Opus encoder + RTCPeerConnection        │
  └─ WebSocket /signal                       ▼
                              [Server Node.js :3975]
                               ├─ HTTP statico + QR + API
                               ├─ Signaling WebSocket (/signal)
                               ├─ Relay nativo (/native-audio, solo localhost)
                               └─ Bonjour/mDNS _wifora._tcp.local
                                          │
              [Control Center daemon :3976, solo 127.0.0.1]
                                          │
        [Listener: iPhone/iPad/Android/PC]
         WebRTC P2P (DTLS-SRTP) ◀──── media diretto dall'host
         WebSocket /signal ◀───────── solo segnalazione

Principio cardine: il media non passa mai dal server. Il Node.js coordina (chi c'è, chi entra con quali credenziali) e l'audio viaggia direttamente dal PC ai dispositivi in peer-to-peer crittografato.

Vita di una sessione

  1. L'host preme Avvia: cattura → DSP → encoder pronti; genera roomId (8 char), hostKey (256 bit) e listenerToken (128 bit).
  2. L'host si registra su /signal; il server crea la stanza e conferma registered.
  3. Il telefono apre il link/QR e si registra come listener con token; il server verifica e notifica all'host listener-joined.
  4. L'host crea una RTCPeerConnection dedicata a quel dispositivo: offer SDP (Opus tunato) → answer → scambio candidati ICE.
  5. Il media parte in DTLS-SRTP diretto. Il server continua a vedere solo metadati.
  6. Ogni secondo il listener riporta la telemetria (telemetry.report) e sincronizza il clock (clock.sync probe/reply/report).
  7. L'ANAE fonde le misure host+listener e, se serve, trasmette una nuova policy audio (bitrate/tier/FEC/stereo).
  8. Alla fine: stop dell'host (room-ended per tutti), leave volontario del listener o espulsione (kicked).

Ciclo di vita delle stanze

Evento Comportamento del server
Host chiude pulito (Stop) Stanza chiusa immediatamente; tutti i listener ricevono room-ended
Host cade anomalo (crash/reload) Grazia di 8 s: rientro con la stessa hostKey ripristina tutto
Listener cade anomalo Grazia di 5 s prima di liberare il posto; riconnessione con stessa sessionId annulla il timer
Listener riconnesso Sostituisce silenziosamente il vecchio socket ("Replaced by new connection") senza consumare capacità
Host riconnesso Sostituisce il vecchio socket host ("Host reconnected") e riceve subito l'elenco listener già presenti
Stanze vuote Cleanup automatico dopo 60 s
Listener espulso sessionId bloccata nella stanza corrente; close 4000 dopo 80 ms

Processi su Windows

  • Menu CLI ↔ Control daemon: il menu garantisce che il daemon (:3976) sia vivo; è il daemon a spawnare lo streamer come figlio marcato --wifora-managed con canale IPC.
  • Takeover porta: se la porta richiesta è occupata da un processo Wifora orfano, viene chiuso (marker → taskkill) prima del riavvio.
  • Shutdown affidabile: IPC grazioso → 2.5 s → taskkill forzato → sweep PowerShell dei processi marcati → verifica porte libere.

Mappa dei moduli sorgente

Percorso Responsabilità
server.mjs Assemblaggio server completo (rooms + relay + http + signaling + TLS + discovery)
src/server/http.mjs Route HTTP, statici, security headers, redirect UA
src/server/websocket.mjs Signaling: registrazioni, routing SDP/ICE, heartbeat, limiti payload
src/server/rooms.mjs Ciclo di vita stanze e grazie di riconnessione
src/server/rate-limiter.mjs Limitatori a finestra fissa per IP
src/server/security.mjs Header di sicurezza, origin allow-list, confronti timing-safe
src/shared/protocol.mjs Envelope di controllo v1 e validazione messaggi
src/audio/capture/wasapi.mjs Spawn helper exe, decoder frame WFR1 con resync
src/audio/capture/native-audio-relay.mjs Relay WS binario verso il tab host (localhost)
src/audio/engine Ring buffer PCM, MediaClock, DriftController
src/audio/profiles.mjs Tier ANAE e profili di trasmissione (fonte unica)
src/transport/ Astrazione transport: base stats, WebRTC peers, prototipo RAOP/AirPlay network-free
public/*.js Client: policy engine, jitter controller, clock sync, playout worklet, device detector, i18n, logger

Nota sul prototipo AirPlay: esiste una macchina a stati RAOP completa nei test (ANNOUNCE/SETUP/RECORD…), deliberatamente senza rete reale. È esplorazione futura: Wifora oggi usa esclusivamente WebRTC.
