Sviluppo & Contribuire

Struttura del repository, tooling, test e convenzioni: tutto ciò che serve per mettere le mani nel codice.

Struttura del repository

├─ server.mjs              # assemblaggio + avvio server
├─ cli-menu.mjs            # menu interattivo terminale
├─ control-center.mjs      # daemon console web (:3976)
├─ logger.mjs              # logging strutturato a livelli
├─ src/
│  ├─ server/              # http, websocket, rooms, rate-limiter, security
│  ├─ shared/protocol.mjs  # envelope controllo v1 + validazioni
│  ├─ audio/               # capture WASAPI, relay nativo, engine, profiles
│  └─ transport/           # base stats, WebRTC, prototipo RAOP (no rete)
├─ public/                 # UI host/listener/control + PWA + worklet
├─ native/wasapi/          # helper C++20 + CMake + script build
├─ test/                   # 17 suite node:test (~56 test)
├─ benchmarks/             # harness riproducibile + CSV/JSON risultati
├─ docs/                   # architettura, performance, sicurezza, releasing
└─ website/                # questo sito + wiki (GitHub Pages)

I test

Runner nativo node --test, zero framework aggiuntivi. Copertura per area:

  • Unit/server: pattern credenziali, timing-safe, rate limiter, origin allow-list, header di sicurezza.
  • HTTP: tutte le route, redirect UA, MIME, traversal 403, limiti QR.
  • WebSocket: registrazioni host/listener con messaggi d'errore esatti, riconnessioni, kick/stop-stream, SDP/ICE routing, protocollo v1 (version/payload/policy/clock-sync), close code 1003/1008/1009.
  • Audio: decoder WFR1 frammentato + resync, coda drop-oldest, ring buffer/MediaClock/DriftController, playout elastico (priming, underrun, fade, correzione rate, overflow).
  • Adattività: tier, isteresi 2/5, health score, jitter controller, chaos test (burst perdita, spike singoli, starvation).
  • Infra: mDNS publisher con Bonjour fake, transport base/WebRTC/RAOP handshake RTSP, session registry.

CI e qualità

  • Matrice: Ubuntu + Windows × Node 18.x / 20.x / 22.x → lint, format:check, test.
  • Sicurezza: job dedicato con npm audit --audit-level=high.
  • Dependabot: npm settimanale (max 10 PR) + GitHub Actions (max 5).
  • Stile: ESM (.mjs), Prettier senza semicolons/single quote/printWidth 120; ESLint con regole no-undef/no-unused-vars.

Convenzioni del progetto

  • Messaggi d'errore user-facing in italiano (coerenza con l'app); identificativi tecnici in inglese.
  • Ogni modulo crea il suo logger: logger.child('Tag').
  • Il protocollo è versionato: campi nuovi → validazione esplicita + bump di versione dell'envelope.
  • Niente segreti nei log; niente dati sensibili in payload broadcast.

Flusso di contribuzione

  1. Fork → branch descrittivo (feat/…, fix/…).
  2. Prima della PR: npm run lint && npm test && npm run format:check.
  3. PR con descrizione chiara del problema/soluzione; se cambi il protocollo, aggiorna i test e la wiki.
  4. Aggiungi una voce sotto [Unreleased] nel CHANGELOG.
  5. Le release seguono SemVer: patch per fix, minor per funzioni, major per breaking — procedura completa in docs/RELEASING.md.

Idee benvenute: sync multi-stanza, equalizzatore per listener, statistiche storiche. Apri prima una discussion/issue per design significativi.
