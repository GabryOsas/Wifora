Pipeline DSP & Codec Opus

Dal mixer di Windows al pacchetto RTP: ogni parametro, nodo per nodo.

Cattura

L'host richiede la cattura con vincoli espliciti per disattivare ogni elaborazione "da call" del browser: 

navigator.mediaDevices.getDisplayMedia({
  video: { displaySurface: 'monitor' },
  audio: {
    echoCancellation: false, noiseSuppression: false, autoGainControl: false,
    highpassFilter: false, channelCount: 2, sampleRate: 48000, latency: 0
  },
  systemAudio: 'include', selfBrowserSurface: 'exclude', surfaceSwitching: 'exclude'
})
  • I track video vengono fermati subito: zero banda sprecata.
  • Se la cattura non contiene audio → errore guidato ("spunta Condividi audio di sistema").
  • Il percorso nativo WASAPI sostituisce questa fase con PCM già a 48 kHz (vedi helper nativo).

Il grafo Web Audio

AudioContext { latencyHint: 0, sampleRate: 48000 }
source ─▶ highpass ─▶ peaking(EQ) ─▶ limiter ─▶ gain ─▶ MediaStreamDestination
                                              └─▶ analyser (VU meter)
Nodo Tipo Parametri
High-pass BiquadFilter 20 Hz, Q 0.707 (Butterworth)
Presence EQ BiquadFilter peaking 3.2 kHz, Q 1.0, gain dipendente dalla modalità
Limiter DynamicsCompressor v. tabella modalità (attack ~1 ms)
Gain volume GainNode transizioni setTargetAtTime τ = 20 ms (niente zipper noise)
Analyser AnalyserNode fftSize 128, smoothing 0.45; VU = max bin / 255

Le tre modalità DSP

Parametro Puro Clarity (default) Voce
High-pass 1 Hz (off) 20 Hz 80 Hz
EQ presence @ 3.2 kHz 0 dB 0 dB +3.5 dB
Limiter threshold 0 dB −1.0 dBFS −1.5 dBFS
Knee / Ratio — / 1:1 3.0 dB / 12:1 2.5 dB / 8:1
Attack / Release — / — 1 ms / 40 ms 1 ms / 50 ms

"Clarity" taglia il rumble sotto i 20 Hz e protegge dal clipping in modo trasparente; "Voce" è pensato per podcast e dialoghi; "Puro" bypassa tutto per chi vuole il segnale intatto.

Profilo Bitrate CBR Framing Uso consigliato

Tuning SDP del codec Opus

Prima dell'offer, l'SDP viene riscritto (tuneOpusSdp) per fissare i parametri esatti: 

a=fmtp:111 minptime=10; ptime=20; maxptime=20; useinbandfec=1; usedtx=0;
            stereo=1; sprop-stereo=1; maxaveragebitrate=256000;
            maxplaybackrate=48000; [cbr=1 solo profilo lowlatency]
ptime=20 — frame da 20 ms: compromesso ottimo latenza/efficienza su Wi-Fi (10 ms solo nel profilo gaming).
useinbandfec=1 sempre attiva — costa ~20–30% di payload ma ripara i singoli pacchetti persi: su LAN è un'assicurazione contro dropout udibili.
usedtx=0 — la DTX (discontinuità nel silenzio) interagisce male con la FEC e crea artefatti in musica/film: disabilitata.
stereo=1 quando tier>1 — mono automatico nei tier più resistenti per dimezzare il carico.
maxaveragebitrate — tetto del tier corrente; l'encoder parte comunque conservativo.
cbr — solo lowlatency: bitrate costante per jitter prevedibilissimo.

In più, il sender imposta maxBitrate, priority: high e networkPriority: high.

Perché proprio 48 kHz?

È il sample rate nativo di Opus fullband e della maggior parte delle catene Windows/modem DAC: evita qualunque resampling lungo la catena, riducendo sia latenza sia artefatti. L'unico punto di conversione residuo (worklet nativo → dispositivo) usa interpolazione lineare con stato continuo.
