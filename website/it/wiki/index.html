Benvenuto nella Wiki di Wifora

Wifora è un server open source che trasmette l'audio del tuo PC Windows a qualsiasi dispositivo connesso alla stessa rete locale — iPhone, iPad, Android o un secondo computer — direttamente dal browser, senza installare app, senza cloud e con una latenza tipica di 35–65 ms.

Questa documentazione spiega tutto il progetto: dall'installazione in 60 secondi fino ai dettagli più profondi del protocollo di rete, del motore adattivo ANAE, della sincronizzazione di clock e del modello di sicurezza. Se qualcosa non è chiaro, apri una issue su GitHub.

Glossario essenziale

Termine Significato
Host Il PC Windows che trasmette l'audio di sistema tramite il browser (Chrome/Edge).
Listener Il dispositivo che riceve l'audio (telefono, tablet o secondo PC).
Codice stanza (roomId) Identificativo di 8 caratteri maiuscoli (es. K7P2M9XA) generato ad ogni trasmissione. Esclude caratteri ambigui come O/0 e I/1.
hostKey Chiave segreta a 256 bit (43 caratteri base64url) che autentica il PC trasmittente sulla stanza.
listenerToken Token opzionale a 128 bit incluso nel QR/link che impedisce a chiunque conosca solo il codice stanza di ascoltare.
ANAE Adaptive Network Audio Engine: il motore che regola automaticamente bitrate e qualità in base allo stato della rete.
DSP Digital Signal Processing: la catena di filtri audio (high-pass, EQ, limiter) applicata prima della trasmissione.
WASAPI Windows Audio Session API: usata dall'helper nativo opzionale per catturare l'audio di sistema a livello OS.
mDNS / Bonjour Protocollo di annuncio dei servizi sulla rete locale: Wifora si publica come _wifora._tcp.local.
PWA Progressive Web App: permette di "installare" Wifora sulla schermata home del telefono.

Requisiti in sintesi

  • PC host: Windows 10/11, Google Chrome o Microsoft Edge, Node.js ≥ 18.
  • Riceventi: qualsiasi browser moderno (Safari iOS 15+, Chrome Android 10+, desktop) — nessuna app.
  • Rete: host e ascoltatori sulla stessa LAN. Si consiglia Wi-Fi 5 GHz (o PC via Ethernet) per la latenza ottimale.

Perché solo Chromium su Windows può trasmettere? Perché è l'unico browser che espone la cattura loopback dell'intero audio di sistema senza driver virtuali. La ricezione invece funziona su qualsiasi browser moderno. Vedi Compatibilità Browser.
