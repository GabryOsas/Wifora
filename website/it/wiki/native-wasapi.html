Helper WASAPI Nativo — wifora-audio.exe

Un piccolo helper opzionale in C++20 che cattura l'audio di sistema con WASAPI loopback e lo consegna al server senza passare dalla cattura del browser.

Perché esiste

  • Più robusto del percorso browser: aggira eventuali limitazioni di getDisplayMedia e dipendenze dal driver grafico.
  • Usa MMCSS "Pro Audio" per ridurre starvation sotto carico CPU, e un loop event-driven con callback.
  • Nessun accesso alla rete: scrive il PCM sullo standard output, punto.

Compilazione

Via script (consigliata)

powershell -ExecutionPolicy Bypass -File native\wasapi\build-wasapi.ps1

Lo script prova in ordine: CMake nel PATH (+ copia dell'exe accanto allo script) → compilazione diretta con cl.exe MSVC → MinGW g++ → ricerca ricorsiva di VsDevCmd/CMake dentro Visual Studio. Se non trova alcun compilatore ti dice esplicitamente che resterai sul percorso browser.

Via CMake manuale

cmake -S native/wasapi -B native/wasapi/build
cmake --build native/wasapi/build --config Release
# binario: native\wasapi\build\Release\wifora-audio.exe

Requisiti: Windows, toolchain C++20 (MSVC consigliato), librerie di sistema ole32, avrt, uuid.

Interfaccia a riga di comando

wifora-audio.exe --list-devices          # elenca gli endpoint attivi (ID + nome)
wifora-audio.exe --stdout                # cattura l'endpoint di default verso stdout
wifora-audio.exe --stdout --device ID    # cattura un endpoint specifico

Protocollo binario "WFR1"

Ogni pacchetto su stdout = intestazione fissa di 32 byte little-endian + PCM Float32 interleaved:

Offset Campo Tipo Valore tipico
0 Magic ASCII[4] WFR1
4 Versione UInt16 1
6 Canali UInt16 2 (stereo)
8 Sample rate UInt32 48000
12 Sample per canale UInt32 dimensione frame corrente
16 Sequenza UInt32 contatore progressivo
20 Riservato UInt32 0
24 Timestamp UInt64 campioni dall'avvio

Note implementative importanti: stdout è aperto in modalità binaria (il text mode di Windows convertirebbe 0x0A in 0x0D 0x0A corrompendo il PCM); i campioni sono sanificati (NaN→0, clamp ±1); input 16/24/32-bit int e float vengono normalizzati e risamplati linearmente a 48 kHz con stato continuo tra pacchetti; il flag SILENT produce silenzio esplicito.

La catena completa

[wifora-audio.exe] ──stdout WFR1──▶ [Server Node]
   decoder con re-sincronizzazione sul magic
   coda max 8 frame, drop-oldest sotto pressione
        │
        ▼ WebSocket ws://localhost:3975/native-audio?room=…&key=…
[frame Float32 grezzi (header già rimosso)] ──▶ [Pagina host]
        │
        ▼ AudioWorklet 'wifora-native-pcm'
   buffer d'avvio ~2 pacchetti (~20 ms), tetto ~60 ms,
   resampling lineare 48 kHz → sample rate del dispositivo,
   underrun → silenzio intenzionale (niente crackle)
        │
        ▼ stessa DSP chain + WebRTC degli altri percorsi
  • Il relay accetta solo il tab host: verifica origin + room + hostKey prima dell'upgrade.
  • Un solo client per stanza: una nuova connessione sostituisce la vecchia ("Replaced by a newer host connection").
  • Backpressure: se bufferedAmount supera 48 KiB il frame viene scartato invece di accumulare latenza.
  • I listener remoti ricevono comunque solo Opus via WebRTC: il PCM nativo non lascia mai il PC.

Come si usa

  1. Compila (vedi sopra). L'exe viene cercato automaticamente in: variabile WIFORA_WASAPI_HELPER → native/wasapi/wifora-audio.exe → native/wasapi/build/Release/wifora-audio.exe.
  2. Sulla pagina host premi "Avvia con WASAPI nativo (sperimentale)" dopo aver creato la stanza.
  3. Per indicare manualmente un percorso diverso: set WIFORA_WASAPI_HELPER=C:\percorso\wifora-audio.exe prima di avviare il server.

Limitazioni: funziona solo su Windows e cattura l'endpoint di rendering (default o selezionato). Non è un microfono: serve per l'audio di uscita del sistema.
