Protocollo di Segnalazione WebSocket

Riferimento completo dei messaggi scambiati su ws(s)://host:3975/signal. Utile per sviluppatori e per il debug con LOG_LEVEL=DEBUG.

Regole di base

  • Messaggi JSON; oltre 24.000 byte → chiusura 1009.
  • JSON malformato → chiusura 1003.
  • Heartbeat: ping del server ogni 10 s, chi non risponde viene terminato.
  • Prima messaggio atteso dal client: sempre register.
Identificatore Pattern Note
roomId ^[A-Z0-9]{8}$ 8 caratteri, charset senza ambiguità
hostKey ^[A-Za-z0-9_-]{43}$ 256 bit base64url, confronto timing-safe
listenerToken ^[A-Za-z0-9_-]{22}$ 128 bit base64url, confronto timing-safe
deviceName sanificato Unicode solo lettere/numeri/punteggiatura sicura, max 60 char

Messaggi client → server

type Chi lo invia Campi principali / effetto
register entrambi {role:"host", roomId, hostKey, listenerToken?} oppure {role:"listener", roomId, listenerToken?, deviceName, deviceType, sessionId?}
offer / answer host / listener {target?, sdp:{sdp,…}} — instradati al peer giusto
candidate entrambi {target?, candidate:{…}} — ICE relay
leave listener uscita volontaria → notifica host (voluntary:true)
stop-stream host chiude la stanza: tutti ricevono room-ended
kick-listener host {target} → kicked + close 4000 dopo 80 ms; rejoin bloccato
listener-disconnected host segnala peer WebRTC morto ma signaling vivo
ping entrambi keep-alive applicativo → risposta pong

Envelope di controllo v1

{ "type": "telemetry.report", "version": 1, "sessionId": "ls_…",
  "deviceId": "…", "timestamp": 1724570000000,
  "payload": { "rttMs": 4.2, "jitterMs": 0.6, "lossPercent": 0 } }

Tipi ammessi: session.start · session.stop · device.announce · audio.policy · telemetry.report · network.degraded · network.recovered · ice.restart · clock.sync · server.capabilities. L'evento audio.policy è riservato all'host; version ≠ 1 o payload invalido vengono rigettati con motivi precisi (unsupported-version, invalid-policy, …). Limiti payload: ≤16 chiavi, valori scalari, bitrate 6.000–512.000, ptime ∈ {10,20,40,60}, |offsetMs| ≤ 10.000, correctionPpm ≤ 200.

Messaggi server → client

type Significato
registered registrazione ok {clientId, sessionId?, hostAvailable}
listener-joined / listener-left un dispositivo entra/esce {clientId, sessionId, deviceName, deviceType, voluntary}
error errore operativo (messaggi in italiano, es. "Nessuna trasmissione attiva per questo codice.")
kicked "Sei stato disconnesso dal PC host." + close 4000
room-ended l'host ha fermato la trasmissione
telemetry.report / clock.sync / audio.policy inoltro degli eventi di controllo al destinatario
server.capabilities {webrtc:true, controlProtocol:1, perClientPolicy:true}
server-shutdown arresto in corso, poi close 4001 (non riconnettersi)

Close code e rate limit

Code Motivo
1000 chiusure normali: "Listener left", "Room ended", "Kicked by host", "Host reconnected", "Replaced by new connection"
1003 JSON non valido
1008 flood: troppi tentativi stanza errata (>8/30s) o auth fallite (>10/30s)
1009 messaggio troppo grande (>24 KB)
4000 espulso dall'host (dopo 80 ms)
4001 server in shutdown — il client smette di riconnettersi
4010 (client-side) riciclo volontario del socket per recovery peer

Rate limit upgrade WebSocket: max 30 connessioni / 10 s per IP (oltre: socket distrutto).
