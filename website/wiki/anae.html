The ANAE Adaptive Engine

ANAE (Adaptive Network Audio Engine) measures real network state every second and slides quality across five tiers — never "flapping" between levels.

The five tiers

Tier Name Bitrate Max RTT Max loss Max jitter
5 Studio Master 256 kbps 25 ms 0.2% 4 ms
4 Studio High 224 kbps 50 ms 0.8% 8 ms
3 Balanced Standard starting tier 160 kbps 85 ms 1.8% 15 ms
2 Anti-Lag Resilient 128 kbps 120 ms 4% 25 ms
1 Ultra-Resilient 96 kbps ∞ ∞ ∞

The active tier is the highest one whose limits are all satisfied. Startup is conservatively Tier 3.

Input measurements

  • Host side (1 Hz): audio remote-inbound-rtp → RTT, jitter, lost packets; candidate-pair fallback; activity detected via packet timestamps.
  • Listener side (1 Hz): report with RTT, jitter, loss, playout delay, audio state, page visibility, jitter target and buffer mode.
  • Merging: per metric the worst of host/listener wins; listener reports count only if fresher than 4 s.
  • EMA smoothing: weight 0.3 for RTT/jitter, 0.4 for loss — a single spike moves nothing.

Anti-flapping hysteresis

  • Downgrade: requires 2 consecutive samples pointing to the same lower tier…
  • …unless things are severe: instant loss ≥ 10%, RTT ≥ 200 ms or health score < 40 → immediate downgrade.
  • Upgrade: requires 5 consecutive good samples and climbs one tier at a time.
  • Any counter-sample resets the opposing counter: no oscillation.

Health score

penalty = loss% × 5.0 + jitterMs × 0.8 + rttMs × 0.2
        + lateFrames × 10 + underruns × 15
score = clamp(100 − penalty, 0, 100)

The weights mirror perceived impact: underruns and late frames hurt more than isolated packet loss.

The adaptive jitter buffer

In parallel to bitrate, the WebRTC jitter target (jitterBufferTarget) moves across four modes:

Mode Target When it activates
ultraLow 22 ms Clean network (default)
balanced 35 ms jitter > 7 ms, loss > 0.7%, RTT > 60 ms, low buffer or drift ≥ 50 ppm
stable 50 ms jitter > 15 ms, loss > 2%, RTT > 110 ms or drift ≥ 100 ppm
recovery 65 ms Underrun, late frames, jitter > 35 ms, loss ≥ 4% or RTT ≥ 220 ms (immediate)

Leaving recovery/balanced again requires the 5-good-samples cycle; underruns jump straight to recovery because an audible gap is worse than 40 extra milliseconds.

How policy is applied

  1. The host broadcasts the audio.policy event: {tier, bitrate, fec, stereo, ptime, cbr}.
  2. The listener updates jitterBufferTarget and feeds the drift correction to the playout worklet.
  3. The host renegotiates bitrate/FEC/stereo on the sender (the SDP already advertises the profile ceilings).

Choosing a manual profile (Low Latency / Hi-Fi / Eco) disables adaptivity: the tier stays fixed. The Adaptive profile is recommended.
