System Architecture

Wifora inside: components, the life of a session, room lifecycle and the source module map.

Components

[Windows PC — Host]
  Browser (Chrome/Edge)          Optional WASAPI helper
  ├─ getDisplayMedia loopback    wifora-audio.exe
  │   └─ Web Audio DSP               └─ stdout Float32 PCM (WFR1)
  ├─ Opus encoder + RTCPeerConnection        │
  └─ WebSocket /signal                       ▼
                              [Node.js Server :3975]
                               ├─ Static HTTP + QR + API
                               ├─ Signaling WebSocket (/signal)
                               ├─ Native relay (/native-audio, localhost only)
                               └─ Bonjour/mDNS _wifora._tcp.local
                                          │
              [Control Center daemon :3976, 127.0.0.1 only]
                                          │
        [Listeners: iPhone/iPad/Android/PC]
         WebRTC P2P (DTLS-SRTP) ◀──── direct media from host
         WebSocket /signal ◀───────── signaling only

Core principle: media never passes through the server. Node.js coordinates (who's here, who joins with which credentials) while audio travels directly from PC to devices as encrypted peer-to-peer.

Life of a session

  1. The host presses Start: capture → DSP → encoder ready; it generates roomId (8 chars), hostKey (256-bit) and listenerToken (128-bit).
  2. The host registers on /signal; the server creates the room and confirms with registered.
  3. The phone opens the link/QR and registers as a listener with its token; the server validates and notifies the host (listener-joined).
  4. The host creates an RTCPeerConnection for that device: SDP offer (tuned Opus) → answer → ICE candidate exchange.
  5. Media flows as direct DTLS-SRTP. The server keeps seeing only metadata.
  6. Every second the listener reports telemetry (telemetry.report) and syncs clocks (clock.sync probe/reply/report).
  7. ANAE merges host+listener measurements and, when needed, broadcasts a new audio policy (bitrate/tier/FEC/stereo).
  8. In the end: host stop (room-ended for all), voluntary listener leave, or kick (kicked).

Room lifecycle

Event Server behavior
Host closes cleanly (Stop) Room closed immediately; every listener receives room-ended
Host crashes/reloads 8 s grace: re-entry with the same hostKey restores everything
Listener drops abnormally 5 s grace before freeing the seat; reconnecting with the same sessionId cancels the timer
Listener reconnects Silently replaces the old socket ("Replaced by new connection") without consuming capacity
Host reconnects Replaces the old host socket ("Host reconnected") and immediately receives the existing listener list
Empty rooms Automatic cleanup after 60 s
Kicked listener sessionId blocked in that room; close 4000 after 80 ms

Windows process architecture

  • CLI menu ↔ Control daemon: the menu ensures the daemon (:3976) is alive; the daemon spawns the streamer as a marked child (--wifora-managed) over IPC.
  • Port takeover: if the requested port is held by an orphan Wifora process, it gets closed (marker → taskkill) before restart.
  • Reliable shutdown: graceful IPC → 2.5 s → forced taskkill → PowerShell sweep of marked processes → port verification.

Source module map

Path Responsibility
server.mjs Full server assembly (rooms + relay + http + signaling + TLS + discovery)
src/server/http.mjs HTTP routes, static files, security headers, UA redirect
src/server/websocket.mjs Signaling: registrations, SDP/ICE routing, heartbeat, payload caps
src/server/rooms.mjs Room lifecycle and reconnection graces
src/server/rate-limiter.mjs Fixed-window per-IP rate limiters
src/server/security.mjs Security headers, origin allow-list, timing-safe comparisons
src/shared/protocol.mjs Control envelope v1 and message validation
src/audio/capture/wasapi.mjs Helper exe spawn, WFR1 frame decoder with resync
src/audio/capture/native-audio-relay.mjs Binary WS relay toward the host tab (localhost)
src/audio/engine PCM ring buffer, MediaClock, DriftController
src/audio/profiles.mjs ANAE tiers and transmission profiles (single source of truth)
src/transport/ Transport abstraction: base stats, WebRTC peers, network-free RAOP prototype
public/*.js Client: policy engine, jitter controller, clock sync, playout worklet, device detector, i18n, logger

Note on the AirPlay prototype: a full RAOP state machine exists in tests (ANNOUNCE/SETUP/RECORD…), deliberately without real networking. It's future exploration: today Wifora uses WebRTC exclusively.
