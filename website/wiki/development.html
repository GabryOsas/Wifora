Development & Contributing

Repository layout, tooling, tests and conventions: everything you need to get your hands in the code.

Repository layout

├─ server.mjs              # server assembly + entry point
├─ cli-menu.mjs            # interactive terminal menu
├─ control-center.mjs      # web console daemon (:3976)
├─ logger.mjs              # structured leveled logging
├─ src/
│  ├─ server/              # http, websocket, rooms, rate-limiter, security
│  ├─ shared/protocol.mjs  # control envelope v1 + validation
│  ├─ audio/               # WASAPI capture, native relay, engine, profiles
│  └─ transport/           # base stats, WebRTC, network-free RAOP prototype
├─ public/                 # host/listener/control UI + PWA + worklet
├─ native/wasapi/          # C++20 helper + CMake + build script
├─ test/                   # 17 node:test suites (~56 tests)
├─ benchmarks/             # reproducible harness + CSV/JSON results
├─ docs/                   # architecture, performance, security, releasing
└─ website/                # this website + wiki (GitHub Pages)

npm scripts

Command Action
npm start Starts the streaming server
npm run menu Interactive CLI menu
npm run console Web Control Center with browser opening
npm test / test:watch node:test suite (watch included)
npm run lint / lint:fix ESLint flat config
npm run format / format:check Prettier
npm run benchmark Benchmark harness → results.csv / summary.json

The tests

Native node --test runner, zero extra frameworks. Coverage by area:

  • Unit/server: credential patterns, timing-safe compares, rate limiter, origin allow-list, security headers.
  • HTTP: every route, UA redirect, MIME, traversal 403, QR limits.
  • WebSocket: host/listener registrations with exact error messages, reconnections, kick/stop-stream, SDP/ICE routing, protocol v1 (version/payload/policy/clock-sync), close codes 1003/1008/1009.
  • Audio: fragmented WFR1 decoder + resync, drop-oldest queue, ring buffer/MediaClock/DriftController, elastic playout (priming, underrun, fade, rate correction, overflow).
  • Adaptivity: tiers, 2/5 hysteresis, health score, jitter controller, chaos tests (loss bursts, single spikes, starvation).
  • Infra: mDNS publisher with fake Bonjour, transport base/WebRTC/RAOP RTSP handshake, session registry.

CI & quality

  • Matrix: Ubuntu + Windows × Node 18.x / 20.x / 22.x → lint, format:check, test.
  • Security: dedicated job running npm audit --audit-level=high.
  • Dependabot: weekly npm (max 10 PRs) + GitHub Actions (max 5).
  • Style: ESM (.mjs), Prettier no-semicolons/single quotes/printWidth 120; ESLint no-undef/no-unused-vars.

Project conventions

  • User-facing error messages are Italian (consistent with the app); technical identifiers are English.
  • Every module creates its own logger: logger.child('Tag').
  • The protocol is versioned: new fields → explicit validation + envelope version bump.
  • No secrets in logs; no sensitive data in broadcast payloads.

Contribution flow

  1. Fork → descriptive branch (feat/…, fix/…).
  2. Before the PR: npm run lint && npm test && npm run format:check.
  3. PR with a clear description of problem/solution; if you change the protocol, update tests and the wiki.
  4. Add an entry under [Unreleased] in the CHANGELOG.
  5. Releases follow SemVer: patch for fixes, minor for features, major for breaking — full procedure in docs/RELEASING.md.

Ideas welcome: multi-room sync, per-listener equalizer, historical stats. Open a discussion/issue first for significant designs.
