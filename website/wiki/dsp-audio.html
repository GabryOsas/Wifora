DSP Pipeline & Opus Codec

From the Windows mixer to the RTP packet: every parameter, node by node.

Capture

The host requests capture with explicit constraints that disable every browser "call-mode" processing:

navigator.mediaDevices.getDisplayMedia({
  video: { displaySurface: 'monitor' },
  audio: {
    echoCancellation: false, noiseSuppression: false, autoGainControl: false,
    highpassFilter: false, channelCount: 2, sampleRate: 48000, latency: 0
  },
  systemAudio: 'include', selfBrowserSurface: 'exclude', surfaceSwitching: 'exclude'
})
  • Video tracks are stopped right away: zero wasted bandwidth.
  • If capture contains no audio → guided error ("tick Share system audio").
  • The native WASAPI path replaces this stage with PCM already at 48 kHz (see the native helper).

The three DSP modes

Parameter Pure Clarity (default) Voice
High-pass 1 Hz (off) 20 Hz 80 Hz
Presence EQ @ 3.2 kHz 0 dB 0 dB +3.5 dB
Limiter threshold 0 dB −1.0 dBFS −1.5 dBFS
Knee / Ratio — / 1:1 3.0 dB / 12:1 2.5 dB / 8:1
Attack / Release — / — 1 ms / 40 ms 1 ms / 50 ms

"Clarity" cuts rumble below 20 Hz and protects from clipping transparently; "Voice" targets podcasts and dialogue; "Pure" bypasses everything for an untouched signal.

Opus SDP tuning

Before the offer, the SDP is rewritten (tuneOpusSdp) to pin exact parameters: 

a=fmtp:111 minptime=10; ptime=20; maxptime=20; useinbandfec=1; usedtx=0;
            stereo=1; sprop-stereo=1; maxaveragebitrate=256000;
            maxplaybackrate=48000; [cbr=1 lowlatency profile only]
ptime=20 — 20 ms frames: the sweet spot between latency and Wi-Fi airtime efficiency (10 ms only in the gaming profile).
useinbandfec=1 always on — costs ~20–30% payload but repairs single lost packets: on LAN it's insurance against audible dropouts.
usedtx=0 — DTX (silence discontinuity) interacts badly with FEC and creates artifacts in music/movies: disabled.
stereo=1 when tier>1 — automatic mono in the most resilient tiers to halve the load.
maxaveragebitrate — current tier ceiling; the encoder still starts conservatively.
cbr — lowlatency profile only: constant bitrate for maximally predictable jitter.

Additionally the sender sets maxBitrate, priority: high and networkPriority: high.

Why exactly 48 kHz?

It's Opus fullband's native rate and the most common Windows/DAC chain rate: it avoids any resampling along the path, reducing both latency and artifacts. The single remaining conversion point (native worklet → output device) uses linear interpolation with continuous state.
