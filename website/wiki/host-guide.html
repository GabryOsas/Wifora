Host Guide — Broadcasting Audio

Everything the broadcasting page (host.html) can do: from the QR code to local recording, from audio profiles to kicking devices.

Starting the broadcast

  1. Press Start Audio Broadcast.
  2. In the browser picker choose Entire Screen.
  3. Tick "Share system audio" and confirm.

Under the hood: capture is requested with tuned constraints (48 kHz, stereo, all browser "call" processing disabled), video tracks are stopped instantly and audio enters the DSP chain described on the DSP page.

Closing the picker without sharing shows "Sharing cancelled by the user". Forgetting the audio track triggers an immediate guided error.

Native WASAPI button (experimental)

Start with native WASAPI uses the locally compiled C++ helper to grab the system mix straight from the Windows audio engine, bypassing the browser path. It must be compiled first: see Native WASAPI Helper.

Session dashboard

Room code and QR

  • Room code: 8 uppercase characters with no ambiguous letters (no O/0, I/1). Regenerated for every new broadcast.
  • QR code: generated server-side (420 px PNG, error correction level M) containing the full URL http://IP:3975/listen.html?room=CODE&token=….
  • LAN URL: copyable with a dedicated button — handy for sending it via chat to someone on the same network.

Status indicator

Status Meaning Internal logic
Connected All good WebSocket alive and no peer beyond degradation thresholds
Waiting No listener yet Signaling active but zero connected peers
Weak signal Network under stress At least one peer with loss > 4% or RTT > 120 ms
Disconnected Signaling dropped WebSocket no longer open (auto-reconnect up to 6 attempts)

Reload-resistant session

Room credentials (roomId + hostKey + listenerToken) are kept in sessionStorage for 12 hours: reloading the page re-attaches the host to the same room. If the socket dies abnormally the server keeps the room recoverable for 8 seconds; a valid reconnect replaces the previous host. A clean stop closes the room for everyone immediately.

Transmission profiles

Profile Bitrate Behavior
Adaptive (Smart Auto) — default 96–256 kbps ANAE switches tiers automatically based on network state (see ANAE)
Gaming & Low Latency 160 kbps Fixed, CBR, 10 ms framing: minimum constant latency
Studio Hi-Fi Master 384 kbps Maximum fidelity, for critical music on excellent networks
Eco 96 kbps Minimum Wi-Fi impact, for speech and long sessions

DSP modes

Mode Processing
Clarity (default) 20 Hz high-pass, −1 dBFS limiter (12:1): transparent rumble cleanup and anti-clipping
Pure Full bypass: filters neutralized, bit-perfect from mixer to codec
Voice 80 Hz low-cut + 3.2 kHz presence +3.5 dB + dedicated limiter: ideal for podcasts/calls

Changes apply with soft transitions (20 ms), no clicks. Full parameters in DSP Pipeline.

Volume and VU meter

  • The PC slider controls pre-transmission gain: it affects what everyone hears (unlike phone volume, which is local).
  • The VU bar shows the instantaneous level computed by the analyser (FFT 128) on the post-DSP signal.

Local recording

The record button saves what you are broadcasting to a file (pre-codec tap, so maximum quality): WebM/Opus format (M4A fallback where needed), filename wifora-CODE-timestamp.webm, chunks written every second. Recording runs entirely on your PC.

Managing connected devices

Every listener appears with its detected name (e.g. "Mario's iPhone", "Galaxy S24", "Windows PC") plus a live telemetry row: 

Ping 4 ms • Jitter 0.6 ms • Buffer 22 ms • Sync ±1.2 ms • 256 kbps • 0.0% loss
  • If a device stops reporting telemetry for > 3.5 s its row becomes "Signal Lost • Reconnecting…" (no fake data).
  • The Kick button disconnects that device (close code 4000 "Kicked by host"); the phone shows "You have been disconnected by the PC host."
  • A listener reconnecting with the same sessionId resumes their seat instead of taking a new one.

Room limits

  • Default 5 simultaneous listeners, configurable 1–32 via WIFORA_MAX_LISTENERS (configuration).
  • Beyond the limit the join attempt gets "The room has reached its listener limit."
  • Above ~8–10 concurrent streams it's the Wi-Fi's turn: on 2.4 GHz RF airtime becomes the bottleneck, not Wifora.

Stopping the broadcast

Stop Broadcast closes the room: every listener receives the room-ended event and a "Broadcast ended" toast. The room code dies with it: a new broadcast means a new code.
