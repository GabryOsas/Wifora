Wifora/Wiki/Welcome

Welcome to the Wifora Wiki

Wifora is an open source server that streams your Windows PC's system audio to any device on the same local network — iPhone, iPad, Android or a second computer — directly in the browser, with no app installs, no cloud, and a typical 35–65 ms latency.

This documentation explains everything about the project: from the 60-second setup to the deepest details of the network protocol, the ANAE adaptive engine, clock synchronization and the security model. If anything is unclear, open an issue on GitHub.

Essential glossary

Term Meaning
Host The Windows PC transmitting system audio through its browser (Chrome/Edge).
Listener The receiving device (phone, tablet or secondary computer).
Room code (roomId) An 8-character uppercase identifier (e.g. K7P2M9XA) generated per broadcast. Ambiguous glyphs like O/0 and I/1 are excluded.
hostKey A 256-bit secret (43 base64url chars) that authenticates the broadcasting PC on the room.
listenerToken An optional 128-bit token embedded in the QR/link that prevents anyone who only knows the room code from eavesdropping.
ANAE Adaptive Network Audio Engine: the motor that automatically adjusts bitrate and quality based on network state.
DSP Digital Signal Processing: the filter chain (high-pass, EQ, limiter) applied before transmission.
WASAPI Windows Audio Session API: used by the optional native helper to capture system audio at OS level.
mDNS / Bonjour Local service advertisement protocol: Wifora publishes itself as _wifora._tcp.local.
PWA Progressive Web App: lets you "install" Wifora on your phone's home screen.

Requirements at a glance

  • Host PC: Windows 10/11, Google Chrome or Microsoft Edge, Node.js ≥ 18.
  • Receivers: any modern browser (Safari iOS 15+, Chrome Android 10+, desktop) — no app needed.
  • Network: host and listeners on the same LAN. Wi-Fi 5 GHz (or Ethernet for the PC) is recommended for best latency.

Why is Chromium-on-Windows required to broadcast? Because it is the only browser exposing full system-audio loopback capture without virtual audio drivers. Reception works on any modern browser. See Browser Compatibility.
