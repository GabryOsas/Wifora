Network, IPs & mDNS Discovery

How Wifora finds your IPs, builds the QR, advertises itself on the network — and what to do when the network misbehaves.

LAN address selection

At startup (and on every /api/network request) the server enumerates IPv4 addresses and filters them:

  • discarded: loopback, internal, link-local 169.254.x.x;
  • virtual adapters filtered by name: Cloudflare WARP, VPN, tunnel, TAP/Wintun, Tailscale, ZeroTier, Docker, Hyper-V, VMware, VirtualBox;
  • private ranges first (192.168.x.x, 10.x.x.x, 172.16–31.x.x).

The first address in the list is the one used in the QR and displayed URLs; the others remain valid ways to reach the same server.

QR code and listening URL

  • The QR is generated server-side (GET /qr?text=…): 420 px PNG, margin 1, error correction M.
  • Its content is the full URL: http://192.168.1.50:3975/listen.html?room=K7P2M9XA&token=AbC…
  • Multiple NICs? The host page shows a copyable current URL; the Control Center lists every adapter with ready links.

Bonjour/mDNS announcement

After the port opens, Wifora publishes the service:

_wifora._tcp.local
name: "Wifora (HOSTNAME:3975)"
TXT:  version=1 · path=/listen.html · transport=http|https · capabilities=webrtc,opus,qr
  • The name includes port and hostname to avoid collisions if you run two instances on one PC.
  • Why the phone doesn't "see" the PC automatically: browsers (Safari included) don't let JavaScript enumerate local mDNS services. The QR/link therefore remains the official path; mDNS exists as a standard announcement for tools and future integrations.
  • In test runtime (--test) the announcement is disabled.

Windows Firewall

  1. On first run Windows asks "Allow access" for Node.js: tick private networks.
  2. Denied by mistake? Control Panel → Firewall → Allowed apps → re-enable Node.js (private).
  3. Quick test from another device: Test-NetConnection 192.168.1.50 -Port 3975 must return TcpTestSucceeded: True.

Common edge cases

  • VPN active: the adapter is filtered from the list, but system routing may still send traffic into the VPN → if the phone can't reach the PC, disable the VPN temporarily.
  • PC hotspot: works great (private subnet); connect the phone to the PC's hotspot.
  • Guest/hotel networks with "AP isolation": clients can't talk to each other → Wifora cannot work there by design (it's a trusted local-network tool, not an internet service).
  • Dual NIC (Ethernet + Wi-Fi): the QR uses the first private IP found; if the phone is on the other network, manually use the right IP from the Control Center list.
