WebSocket Signaling Protocol

Complete reference of the messages exchanged on ws(s)://host:3975/signal. Useful for developers and for debugging with LOG_LEVEL=DEBUG.

Ground rules

  • JSON messages; beyond 24,000 bytes → close 1009.
  • Malformed JSON → close 1003.
  • Heartbeat: server ping every 10 s; silent clients are terminated.
  • The first expected client message is always register.
Identifier Pattern Notes
roomId ^[A-Z0-9]{8}$ 8 chars, ambiguity-free charset
hostKey ^[A-Za-z0-9_-]{43}$ 256-bit base64url, timing-safe compare
listenerToken ^[A-Za-z0-9_-]{22}$ 128-bit base64url, timing-safe compare
deviceName Unicode-sanitized letters/digits/safe punctuation only, max 60 chars

Messages: client → server

type Sent by Main fields / effect
register both {role:"host", roomId, hostKey, listenerToken?} or {role:"listener", roomId, listenerToken?, deviceName, deviceType, sessionId?}
offer / answer host / listener {target?, sdp:{sdp,…}} — routed to the right peer
candidate both {target?, candidate:{…}} — ICE relay
leave listener voluntary exit → host notified (voluntary:true)
stop-stream host closes the room: everyone receives room-ended
kick-listener host {target} → kicked + close 4000 after 80 ms; rejoin blocked
listener-disconnected host reports a WebRTC peer dead while signaling lives on
ping both application keep-alive → answered with pong

Control envelope v1

{ "type": "telemetry.report", "version": 1, "sessionId": "ls_…",
  "deviceId": "…", "timestamp": 1724570000000,
  "payload": { "rttMs": 4.2, "jitterMs": 0.6, "lossPercent": 0 } }

Allowed types: session.start · session.stop · device.announce · audio.policy · telemetry.report · network.degraded · network.recovered · ice.restart · clock.sync · server.capabilities. The audio.policy event is host-only; version ≠ 1 or invalid payloads are rejected with precise reasons (unsupported-version, invalid-policy, …). Payload limits: ≤16 keys, scalar values, bitrate 6,000–512,000, ptime ∈ {10,20,40,60}, |offsetMs| ≤ 10,000, correctionPpm ≤ 200.

Messages: server → client

type Meaning
registered registration ok {clientId, sessionId?, hostAvailable}
listener-joined / listener-left a device joins/leaves {clientId, sessionId, deviceName, deviceType, voluntary}
error operational error (Italian messages, e.g. "Nessuna trasmissione attiva per questo codice.")
kicked "Sei stato disconnesso dal PC host." + close 4000
room-ended the host stopped the broadcast
telemetry.report / clock.sync / audio.policy forwarded control events to the destination
server.capabilities {webrtc:true, controlProtocol:1, perClientPolicy:true}
server-shutdown shutdown in progress, then close 4001 (do not reconnect)

Close codes & rate limits

Code Reason
1000 normal closures: "Listener left", "Room ended", "Kicked by host", "Host reconnected", "Replaced by new connection"
1003 invalid JSON
1008 flood: too many wrong-room attempts (>8/30s) or failed auths (>10/30s)
1009 message too large (>24 KB)
4000 kicked by the host (after 80 ms)
4001 server shutting down — clients stop reconnecting
4010 (client-side) voluntary socket recycle for peer recovery

WebSocket upgrade rate limit: max 30 connections / 10 s per IP (beyond: socket destroyed).
